# Don't Read, Look! — لا تقرأ… شوف!

اختبار ستروب (Stroop) جماعي لفعالية **GDGoC DevFest**: تظهر كلمة لون مكتوبة بلون مختلف، وعلى كل لاعب أن يضغط **لون الخط لا معنى الكلمة** بأسرع ما يمكن. يلعب حتى 60 شخصًا معًا من هواتفهم، والمضيف يعرض اللعبة على شاشة كبيرة.

| | الرابط |
|---|---|
| صفحة اللاعبين (الموبايل) | https://dont-read-look.web.app |
| صفحة المضيف (الشاشة الكبيرة) | https://dont-read-look.web.app/host |

---

## يوم الفعالية

1. افتح **/host** على الجهاز الموصول بالبروجكتر، واضغط `F` أو زر ملء الشاشة. تُنشأ غرفة بكود من 4 أرقام تلقائيًا.
2. يمسح اللاعبون رمز QR (يفتح الصفحة مع الكود جاهزًا) أو يفتحون `dont-read-look.web.app` ويكتبون الكود، ثم أسماءهم.
3. اضغط **ابدأ اللعبة** (أو `Space`). بعد كل سؤال تظهر الإجابة الصحيحة وأسرع 3 والترتيب؛ اضغط **التالي** (أو `Space`).
4. في النهاية: منصة التتويج. **لعبة جديدة** تعيد نفس اللاعبين إلى الانتظار بأسئلة جديدة، و**غرفة جديدة** تحذف الغرفة الحالية وتنشئ غيرها.

نصائح:
- الصوت يبدأ بعد أول ضغطة على الصفحة (سياسة المتصفحات). اضغط في أي مكان على صفحة المضيف قبل البدء.
- زر × بجانب اسم اللاعب يُخرجه (اضغطه مرتين للتأكيد). اللاعب المُخرج لا يستطيع العودة لنفس الغرفة.
- اللاعب الذي يغلق المتصفح ويعود يرجع لنفس مكانه ونقاطه. وإن أُغلقت صفحة المضيف فافتحها مجددًا على نفس الجهاز والمتصفح لتعود لنفس الغرفة.
- إذا أجاب كل اللاعبين المتصلين ينتهي السؤال مبكرًا تلقائيًا. زر **إنهاء الآن** ينهيه يدويًا.
- لعمى الألوان: لكل لون رمز ثابت على زره، وزر **A** في صفحة اللاعب يُظهر اسم اللون على الأزرار.

### تعديل الألوان

كل الألوان وقواعد التشابه في `public/js/game-config.js`. إن ظهر لونان متقاربين على البروجكتر، عدّل `hex` أو أضف زوجًا إلى `SIMILAR_PAIRS`، ثم انشر (`firebase deploy --only hosting`). خلفية بطاقة الكلمة داكنة افتراضيًا (`wordStage: 'dark'`) لأن الأصفر والسماوي يصعب قراءتهما على الأبيض في البروجكتر؛ غيّرها إلى `'light'` إن أردت.

## ربط Firebase خطوة بخطوة

هذه الخطوات نُفّذت بالفعل على مشروع `dont-read-look`. أعدها كما هي إن احتجت ربط مشروع آخر أو إعادة النشر.

**1. ثبّت Firebase CLI وسجّل الدخول** (مرة واحدة على الجهاز):
```powershell
npm install -g firebase-tools
```
```powershell
firebase login
```

**2. ادخل مجلد اللعبة.** الملف `.firebaserc` يربط المجلد بالمشروع `dont-read-look` تلقائيًا. لمشروع آخر:
```powershell
firebase use --add
```

**3. سجّل تطبيق ويب** (مرة واحدة لكل مشروع):
```powershell
firebase apps:create WEB "Don't Read, Look!"
```
احفظ `App ID` الذي يظهر (مثل `1:78318246297:web:...`).

**4. اجلب الإعدادات وضعها في `public/js/firebase-config.js`:**
```powershell
firebase apps:sdkconfig WEB <APP_ID>
```
انسخ القيم إلى الكائن `firebaseConfig`، وتأكد أن `databaseURL` هو رابط قاعدتك. لمشروعنا القاعدة في أوروبا، فالرابط:
`https://dont-read-look-default-rtdb.europe-west1.firebasedatabase.app`
(يمكنك التحقق منه بـ `firebase database:instances:list`).

**5. فعّل الدخول المجهول وانشر القواعد** — `firebase.json` يحتوي `"auth": { "providers": { "anonymous": true } }`:
```powershell
firebase deploy --only auth,database
```

**6. انشر الموقع:**
```powershell
firebase deploy --only hosting
```
أو كل شيء مرة واحدة: `firebase deploy`. الرابط: `https://<project-id>.web.app` وصفحة المضيف `/host`.

**7. التجربة محليًا قبل النشر** (يستخدم قاعدة البيانات الحقيقية):
```powershell
firebase serve --only hosting
```
ثم افتح `http://localhost:5000/host`. لتجربة عدة لاعبين في نفس المتصفح أضف `?profile=` باسم مختلف لكل تبويب، مثل `http://localhost:5000/?room=1234&profile=p1`.

> القيم في `firebase-config.js` ليست سرية، فهي تُرسل لكل متصفح على أي حال. الحماية في قواعد القاعدة.

## كيف تعمل

```
rooms/<code>/
  meta        {hostUid, createdAt, state, current, total, duration}   ← المضيف فقط يكتب
  questions   كل الأسئلة (يولّدها المضيف عند الإنشاء)                  ← المضيف فقط يقرأ
  live        السؤال الحالي فقط + startAt (ServerValue.TIMESTAMP)      ← الجميع يقرأ
  players/<uid>   {name, slot, key, joinedAt}                          ← اللاعب ينشئ سجله مرة واحدة
  slots/<0..59>   uid    ← 60 مقعدًا: هذا ما يفرض حد 60 لاعبًا
  names/<key>     uid    ← يمنع تكرار الاسم داخل الغرفة
  presence/<uid>  true   ← متصل الآن؟ (يُحذف تلقائيًا عند الانقطاع)
  answers/<q>/<uid>  {c: اللون, t: ServerValue.TIMESTAMP}               ← مرة واحدة فقط
  scores/<uid>    {score, time, correct, rank, n, last}                ← المضيف يكتب، اللاعب يقرأ نتيجته فقط
  results/<q>     {fastest, counts, startAt}                           ← للمضيف
  kicked/<uid>    true
roomIndex/<code>  وقت الإنشاء   ← لتفادي تكرار الكود ولحذف الغرف الأقدم من 24 ساعة
```

- **الزمن:** زمن الإجابة = `t` (وقت الخادم عند وصول الإجابة) − `startAt` (وقت الخادم عند بدء السؤال). ساعة الجهاز لا تدخل في الحساب.
- **النقاط:** صحيح = `1000 − 500 × (الزمن ÷ المدة)`، أي من 1000 فورًا إلى 500 عند نهاية المؤقت. الخطأ أو عدم الإجابة = 0.
- **التعادل:** يتقدّم صاحب أقل مجموع زمن للإجابات الصحيحة. إن تساوى الاثنان يتشاركان الترتيب.
- **التسلسل:** عند انتهاء المؤقت يغيّر المضيف الحالة إلى `closed` أولًا (فترفض القواعد أي إجابة بعدها)، ثم يقرأ الإجابات ويحسب النقاط ويكتبها مع الحالة `reveal` في عملية واحدة.

## حدود الأمان (اقرأها)

ما تضمنه القواعد:
- اللاعب يكتب فقط: سجله مرة واحدة (مع مقعد واحد واسم واحد في نفس العملية)، حالة اتصاله، وإجابته **مرة واحدة لكل سؤال** — فقط أثناء السؤال الحالي، وبلون من الأزرار الأربعة، وبوقت الخادم، وقبل نهاية المؤقت + ثانيتين.
- لا يستطيع اللاعب تعديل أو حذف إجابته، ولا قراءة إجابات الآخرين أو نقاطهم، ولا قراءة الأسئلة القادمة، ولا الكتابة في `meta` أو `live` أو `scores` أو مقاعد وأسماء غيره.
- الغرفة ملك من أنشأها (`hostUid`)؛ لا يستطيع غيره تعديلها. أي مستخدم يستطيع حذف غرفة **أقدم من 24 ساعة** فقط.
- اللاعب المُخرَج لا يستطيع الدخول مجددًا بنفس الهوية.

ما **لا** تمنعه القواعد (حدود طبيعية لأي لعبة ويب بلا خادم):
1. **الهوية مجهولة:** أي شخص يستطيع إنشاء هوية جديدة (مثل مسح بيانات المتصفح)، فاللاعب المُخرَج يستطيع العودة باسم جديد. الحد الأقصى 60 مقعدًا يحدّ من ذلك، والمضيف يستطيع الإخراج مجددًا.
2. **الغش بسكربت:** لون الخط يجب أن يصل للاعب ليراه، لذلك يستطيع مبرمج كتابة سكربت يجيب فورًا. لا يمكن منع ذلك من القواعد؛ راقب الأزمنة غير الطبيعية (أقل من ~0.3 ثانية).
3. **المضيف موثوق:** من يملك الغرفة يكتب النقاط بنفسه؛ قواعد القاعدة لا تتحقق من صحة حسابه.
4. **من يعرف الكود** يستطيع قراءة `meta` و`live` وقائمة الأسماء (`names`) لتلك الغرفة. الإجابات والنقاط تبقى خاصة.
5. **إنشاء الغرف غير محدود:** لا يوجد حد لعدد الغرف؛ الغرف القديمة تُحذف فقط عند إنشاء غرفة جديدة. لحماية أقوى من البوتات فعّل **App Check** لاحقًا.
6. **الشبكة:** الزمن يُقاس عند وصول الإجابة للخادم، فاللاعب على شبكة بطيئة يخسر بضعة أجزاء من الثانية.
7. **الأسماء غير مراقبة:** المضيف يستطيع إخراج أي اسم غير لائق.

## مشاكل شائعة

- **«تعذّر تسجيل الدخول المجهول»:** شغّل `firebase deploy --only auth` أو فعّل Anonymous من Console → Authentication → Sign-in method.
- **لا يحدث شيء / PERMISSION_DENIED في الـ Console:** تأكد أن القواعد منشورة (`firebase deploy --only database`) وأن `databaseURL` صحيح.
- **رمز QR يفتح localhost:** هذا متوقع عند التشغيل المحلي. ضع `joinBaseUrl: 'https://dont-read-look.web.app/'` في `game-config.js` إن أردت أن يفتح الموقع المنشور.
